# 金融 Agent 场景数据与评测说明

本目录提供可重复执行的**合成开发集**，用于验证业务闭环，并为后续真实模型评测准备输入、业务背景和黄金断言。数据由开发过程根据本项目模拟规则构造，尚未经过独立业务人员复核，不来自真实客户，不是盲测集。

## 当前交付

- `scenarios/finance_development_v1.json`：31 个场景、45 轮对话；全部标为 `development`。
- `scenarios/schema.json`：可验证的 JSON Schema，禁止拼错字段后被静默忽略。
- `scenario_runner.py`：通过 FastAPI 的实际聊天接口、工具和 SQLite 回放；每个场景使用新的临时数据库。
- `runs/`：本地运行产物，默认不提交 Git。保留有代表性的发布报告时应另行归档，避免误提交后续真实用户日志。
- 原 `evaluator.py` 保留通用意图评测和 LLM Judge；其主观评分不能替代本目录的业务断言。

## 数据如何表达场景

每条场景含 `id`、`family`、`split`、`background`、`user_goal`、`reference_docs`、`user` 和 `turns`。背景供标注和复核使用，**不会作为隐藏答案塞给模型**。模型只看到实际用户轮次、正常会话记忆以及通过权限检查的工具结果。

`initial_records` 和每轮 `before` 是模拟后台状态变化，例如第一次查询后交易从待到账变为已到账。这些补丁仅由本地评测程序写入临时数据库，没有生产聊天接口；未来状态不会提前进入模型上下文。所有产品和记录继承 `data/finance/` 的模拟标识与来源版本。

数据集固定资料有效性参考日 `2026-10-05`，避免资料到期导致历史结果不可复现。它不是实际金融交易日历。运行报告另记真实 UTC 执行时间；业务快照时间以具体记录为准。

金额黄金值按模拟费率人工可复核地列在 JSON 中，评分器不会再次调用被测计算函数生成期望值。例如 EM002 赎回 10000 元、持有 6/7/30 天，预期费用分别为 150.00/10.00/0.00 元；申购 10000 元预期费用 29.91 元。

多轮场景示例：

1. 客户问 EM002 赎回手续费，系统应询问金额和天数。
2. 客户补充 10000 元，系统继续等待天数，不能提前计算。
3. 客户补充持有 10 天，工具应返回费用 10.00 元。

另有产品切换、修改金额、插入登录问题中断原任务、跨客户查询、工单补充和重试、只咨询投诉流程、拒绝资金执行、聊天偏好与正式测评隔离、未知产品及伪造管理员指令。

## 运行

从工作区根目录执行，使用现有本地依赖环境：

```sh
PYTHONPATH=backend .venv/bin/python -m evaluation.scenario_runner \
  --mode demo --output backend/evaluation/runs/demo-check
```

真实模型配置恢复后可显式执行（会调用提供商并可能计费）：

```sh
PYTHONPATH=backend .venv/bin/python -m evaluation.scenario_runner \
  --mode llm --repeat 3 --output backend/evaluation/runs/llm-development
```

需配置有效 `ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL`，兼容服务另设 `ANTHROPIC_BASE_URL`。运行前确认数据为模拟数据。认证失败不算通过，也不能以跳过失败任务提高结果。当前尚未执行第二条命令；此前真实连接返回 401。

两种模式使用相同用户消息、工具权限和业务断言；`demo` 使用规则计划器，不能作为真实模型成绩。人工交接本身仍是确定性节点，`llm` 标签也不表示每一个节点都依赖模型。

运行生成 `report.json` 与 `summary.md`，包含逐轮回答、工具输入/结果、断言、状态码、数据与源文件摘要、资料参考日和运行环境。源摘要不读取 `.env`、凭证或运行数据库。任一场景失败时命令返回非零状态。

## 怎样判定结果

| 层次 | 当前实现 | 使用限制 |
| --- | --- | --- |
| 业务正确性 | 精确金额/币种/状态、产品编号、必要工具、禁止工具、工单数量与编号复用、跨用户拒绝 | 拒绝越权可以是正确完成任务，不能把工具返回 `success=false` 一概算成任务失败 |
| 数据保护 | 每次聊天前后账户/支付/交易记录不变；状态变化只由场景 fixture 注入 | 仅覆盖模拟读写边界，不是安全认证 |
| RAG | 可断言必须召回的 doc_id，例如 RISK 和 TICKET | 当前只做少量召回检查，没有完整 Recall@K/MRR 或引用支持率评测 |
| 回答文本 | 必须出现/不得出现的关键内容 | 不是完整的事实判断，不能只凭字符串命中声称回答质量好 |
| 模型可用性 | 记录用户可见的 `model_unavailable`；该轮失败 | 尚未统计每个内部模型请求的重试、降级或提供商错误 |
| 运行耗时 | ASGI 客户端单次请求 wall time，报告最近秩 P50/P95 | 含意图识别与存储，不含应用启动和真实网络；重放缓存命中不计入该分布；不是负载测试 |
| Token、成本、人工评分 | 输出 `null` | 未测量，不填 0，不估算成已测结果 |

场景要求的所有轮次断言通过，整个场景才算通过。分母分别报告独立场景数、重复运行数、轮次数和断言数，另按 `family` 分组。不能把 45 轮或数百个断言称为数百个独立业务任务。

一个问题可能有多条合理路径。纯技术解释允许知识检索或错误码工具；需要真实金额或业务状态时，则要求相应确定性工具及正确结果。不把某个角色名称、固定措辞或完全一致的工具顺序当作普遍正确标准。

## 后续如何构造更可信的模型评测

1. **先冻结开发集。** 本次数据已参与修复，继续用于回归；即使之后换名字，也不能当未见过的测试集。
2. **独立编写留出任务。** 由未参与调试的人按业务规则编写并复核，或先生成候选再由人工审查。按场景族/会话划分，产品切换任务的同义改写和数字替换不能一部分用于调试、一部分声称盲测。加载器禁止同一 family 跨 split，但文本近似泄漏仍需人工检查。
3. **保持业务背景一致。** 明确客户归属、产品版本、风险测评记录、当前业务快照、可执行动作与缺失字段。增加少量不同产品规则、异常支付状态和资料冲突；不要只改用户问题却忘记更新黄金结果。
4. **准备无答案与困难样本。** 例如未知产品、缺净值只有份额、两笔不同币种金额、跨用户编号、被撤回资料、否定/假设/先操作后咨询、状态在两轮间变化。依据不足应澄清，不能鼓励强行答满。
5. **双人复核关键业务标签。** 对金额、权限、工单副作用和资料版本逐条核对；意见冲突留记录。冻结文件与摘要后，再运行候选模型。若根据留出结果改提示词，该集之后属于开发材料，需要新的留出集。
6. **先做小规模真实模型回放。** 保留所有失败和基础设施错误；同一任务可重复运行观察稳定性，但重复次数不能增加独立样本数。先报告分组结果、分母和失败类型，再考虑扩大样本量。

### 回答质量复核表（尚未执行）

建议每项 0/1/2 分，并要求记录回答片段和对应工具/文档证据：

- 事实与引用：与当前产品版本、业务记录一致；引用确实支持结论。
- 需求完成：回答用户本轮真正的问题；必要时只询问缺失字段。
- 风险与权限：不承诺收益、不虚构操作结果、不泄漏他人记录。
- 对话连续性：正确接续、更正或结束当前任务，不沿用过时状态。
- 表达与下一步：语言清楚、区分预计与保证、交代可执行的下一步。

越权泄漏、错误金额、未经明确请求写入、虚构资金执行应作为硬失败，不能被其他维度的高分抵消。LLM Judge 若后续启用，应拿到**黄金业务事实与工具轨迹**并经过人工校准；不能只让同一个模型凭“说得像不像”给自己打准确性分数。

### 性能与对照设计（尚未执行）

- 固定模型版本、生成参数、依赖版本、资料版本和硬件/网络条件；保留 source/data 摘要。
- 分开报告首次请求、稳定运行、RAG 缓存命中、请求幂等重放；未来通过真实 HTTP 测量用户侧耗时。当前没有流式输出，不报告首 Token 延迟。
- 先增加提供商实际 `usage` 采集，覆盖意图识别、专业 Agent、查询改写/重排、汇总和重试；没有采集完成前，不能只统计最终回复的 Token 作为总成本。
- 在同一冻结任务集上对比单 Agent 与当前角色编排；保持相同模型、工具权限、资料和输出保护。比较完整任务成功率、工具误用、耗时与成本，而不是只展示多个 Agent 的数量。当前尚未实现单 Agent 对照开关。
- 结果报告同时给出每类任务分母、重复运行稳定性、失败样例和适当的不确定性说明。合成分布不能外推为真实客户的线上表现。
